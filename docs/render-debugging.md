# تشخيص بدء السيرفر على Render

في 22 أكتوبر 2026 نجح بناء الويب، ونجحت خدمة OSRM عبر HTTPS. نجح أيضًا
بدء نسخة السيرفر المنشورة بالـcommit `c1c69e4` في وضع production باستخدام
MongoDB وRedis محليين ومعزولين؛ أعاد health وready حالة ناجحة، وبدأ HTTP
خلال نحو 2.6 ثانية. هذه تجربة محلية وليست إثباتًا لوصول Render لقواعد البيانات.

فحص بيانات الاتصال الخاصة بالملف المحلي دون كتابة بيانات أكد نجاح MongoDB
وRedis وOSRM، وعدم وجود حسابات بكلمة المرور التجريبية. قاعدة MongoDB المحددة
كانت فارغة. الاتصال بـRedis في الملف المحلي غير مشفر؛ هذه نقطة تجهيز إنتاج
منفصلة وليست سببًا مثبتًا لفشل النشر الحالي.

سبب فشل محاولات Render الأولى كان غياب `ROUTING_BASE_URL`. أما المحاولات
الأحدث ذات الرسالة العامة فلم يتحدد سببها بعد، والرابط الأساسي لم يرد على
health أو ready خلال 45 ثانية وقت الفحص.

## جمع دليل من بيئة Render الفعلية

في خدمة **waselhaapp** الأساسية، حدّث **Settings → Start Command** إلى:

```text
node scripts/diagnose-render.mjs --start
```

احتفظ بـRoot Directory فارغًا وبأمر البناء الحالي. احفظ الإعداد وأعد نشر
أحدث commit، ثم افتح Runtime logs للمحاولة الجديدة وابحث عن `render_diagnostic`.
لا تحتاج إضافة أسرار جديدة أو نسخ ملف البيئة إلى GitHub.

تطبع الأداة أسماء المتغيرات وحالة وجودها فقط، ثم تفحص MongoDB ping وRedis
ping وطلب مسار عام بواسطة عميل السيرفر الحالي. لا تنشئ فهارس أو مستخدمين أو
طلبات، ولا تنفذ seed أو تعديلات قاعدة بيانات. تنفذ هذه الفحوص بالتوازي مع
مهل قصيرة، ثم تبدأ نقطة الدخول الأصلية للسيرفر. تظل حراس الإنتاج وآلية
بدء السيرفر كما هي، بما فيها تهيئة الفهارس والعمال بعد نجاح بدء التطبيق.

| phase / نتيجة | معنى الدليل والخطوة التالية |
|---|---|
| environment ثم config يفشل | أصلح أسماء/قيم متغيرات الخدمة؛ وجود ملف محلي لا يضبط Render |
| mongo مع authentication أو code 18 | راجع بيانات مستخدم Atlas في Environment دون نشرها |
| mongo مع authorization أو code 13 | راجع صلاحيات مستخدم قاعدة البيانات |
| mongo مع dns أو timeout | افحص DNS وشبكة Atlas وNetwork Access لعناوين خروج الخدمة؛ لا تفترض أن timeout يثبت مشكلة allowlist وحدها |
| redis يفشل | راجع رابط Redis الحقيقي، auth، TLS وقواعد الوصول، وفق reason/code |
| routing يفشل | افحص رابط OSRM والخمول/مهلة الخطة المجانية |
| الفحوص تنجح ثم application_start يفشل | استخدم code الآمن وسجل التطبيق لتحديد الخطوة التالية أثناء بدء التطبيق |
| لا تظهر أي render_diagnostic | تحقق من Start Command والـcommit وRoot Directory وسجل فشل بدء العملية في Render |

السجلات تحتوي فئة الخطأ ورمزه فقط؛ لا تحتوي نص الاستثناء الخام أو stack
أو بيانات الاتصال أو إحداثيات المستخدمين. طلب المسار يستخدم نقاط طرق عامة
ثابتة فقط. حالة المضيف والمنفذ تطبع كقيم منطقية. ظهور redisTlsConfigured=false
لا يُصلح بتغيير `redis://` إلى `rediss://` دون تفعيل TLS على الخدمة نفسها.

بعد تحديد السبب وإصلاحه والتحقق من `/api/ready`، يمكن إعادة Start Command إلى:

```text
node backend/src/server.js
```

## التحقق من حماية السجلات

```sh
node --test scripts/test-diagnose-render.mjs
```

لا تشغّل الأداة بـ`--start` محليًا باستخدام بيانات قاعدة الإنتاج لغرض الاختبار:
هذا الخيار يبدأ السيرفر الأصلي وعماله المعتادين. لتشخيص اتصالات البيئة فقط،
شغّلها دون `--start` مع متغيرات بيئة العملية؛ لا تقرأ الأداة ملفات `.env` المحلية.

المراجع: [تشخيص Render](https://render.com/docs/troubleshooting-deploys)،
[فحوص الصحة](https://render.com/docs/health-checks).
